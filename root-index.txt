<section class="stack">
<p class="eyebrow">The problem</p>
<h2>The invoice is a bad alerting tool.</h2>
<div class="cards3">
<div class="card"><h3>Bill shock</h3><p>A retry loop or a runaway agent can burn 5x your normal spend overnight. Most people find out 30 days later, when the invoice lands.</p></div>
<div class="card"><h3>Split spend</h3><p>Every provider has its own usage page, and each one shows yesterday's totals. Nobody has the one number that matters right now.</p></div>
<div class="card"><h3>Dashboards don't page you</h3><p>Observability tools are built for debugging sessions you have to open. Spikewatch only speaks when something is wrong.</p></div>
</div>
</section>

<h2>Set it up once. Hear from it rarely.</h2>

<section class="stack" id="faq">
<p class="eyebrow">FAQ</p>
<h2>Fair questions.</h2>
<div class="faq">
<details><summary>Is my API key safe?</summary><p>You create a read-only key (for Anthropic, an Admin API key scoped to usage and cost reports). It can read usage numbers and nothing else - it cannot make requests, change settings, or see prompts and responses. Keys are stored encrypted, and the detection code that uses them is open source.</p></details>
<details><summary>Which providers does it watch?</summary><p>Anthropic first - usage and cost reports through the Admin API are confirmed working. OpenAI, Google and OpenRouter are added only after their usage data access is confirmed. The live checker on this site already works with Anthropic usage reports today.</p></details>
<details><summary>Will it cap or switch off my spend?</summary><p>No. Spikewatch warns a human in time to act; it never touches your service. If you want hard caps, set them at your provider - Spikewatch makes sure you find out before it comes to that.</p></details>
<details><summary>Why hourly and not real time?</summary><p>Provider usage APIs update on a delay and rate-limit reads, so hourly is the fastest honest cadence. A loop that starts at 2am is caught by 3am, not on the 30-day invoice.</p></details>
<details><summary>Who runs this?</summary><p>One founder. Signup, billing, the hourly checks and the alerts are fully automated - there is no onboarding call and no support queue. The detection engine is open source and the same code runs for every customer.</p></details>
